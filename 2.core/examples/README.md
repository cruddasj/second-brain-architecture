# Worked examples

These fictional records illustrate the templates without adding personal knowledge,
preferences, approved sources or decisions to a deployed instance.

Read the [project](saas-evaluation/project.md), follow its [source note](saas-evaluation/source-note.md)
to the [trial report](saas-evaluation/trial-report.md), then inspect the [decision](saas-evaluation/decision.md).
The report preserves observations; the note interprets evidence and uncertainty;
the project owns progress; the decision owns the chosen option and review criteria.

In a real instance, evidence belongs in `sources/raw/`, notes in `sources/notes/`,
and project/decision records in `knowledge/projects/`. Obtain save authority,
record approved source scope, generate fresh record and transaction UUIDs, update
the index and apply relationship and theme policies before promoting real claims.
No live source or theme approval is implied here. The UUIDs and dates below are
illustrative; the shared transaction demonstrates a single related save.

Examples stay outside live knowledge and the explorer's knowledge graph. They can
be read through its repository Markdown reader. Never treat these fictional facts
as confirmed knowledge about a user.
